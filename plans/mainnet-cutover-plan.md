# План: перевод на mainnet (реальные деньги)

Составлен 2026-07-25 по итогам полного прогона фаз 1–6 плана `crypto-payments-rake-plan.md`
на testnet. Всё описанное ниже **не выполнено** — это чеклист на день переключения.

## Контекст

Прод `tgp.isgood.host` работает на Crypto Pay **testnet** (приложение «Buckram Wisent App»,
@CryptoTestnetBot). Проверены живьём: депозиты игроков, пополнение bot bankroll реальным
инвойсом, рейк на house-аккаунт, вывод игрока через `transfer`, реконсиляция пропущенных
вебхуков, инвариант денег. Схема, код и админка к боевому режиму готовы — меняются
конфигурация, платёжное приложение и состояние БД.

## ⚠️ Главный риск переключения

В БД сейчас **14 326 фишек**, обеспеченных **testnet-USDT** (кошелёк приложения 154.9 USDT).
Если подменить токен на боевой, не тронув балансы, эти фишки станут правом вывести ~$143
настоящих денег, которых никто не вносил. Первый же вывод опустошит боевой кошелёк.

**Следствие: чистка экономики обязательна и делается ДО того, как в конфиг попадёт боевой токен.**

Второй риск того же рода — фишки, «зависшие» в оперативной памяти. `TableManager` держит стеки
сидящих игроков в `Game`-состоянии, а не в БД. Если обнулить балансы, пока кто-то сидит за столом,
его стек переживёт чистку и при выходе вернётся на баланс — то есть будут созданы фишки из воздуха.
**Чистку делать только при остановленном контейнере `app`.**

## Фаза 4. Конфигурация `/opt/tg-poker/.env`

| Переменная | Сейчас | Поставить |
|---|---|---|
| `CRYPTO_PAY_TOKEN` | testnet-токен | боевой токен |
| `CRYPTO_PAY_TESTNET` | `true` | `false` |
| `BOT_TOKEN` | тестовый бот | токен боевого бота |
| `BOT_USERNAME` | `Testpoke_bot` | боевой бот |
| `WITHDRAWAL_MIN_HANDS` | не задана (=0) | `50` |
| `MONEY_INVARIANT_BASELINE_CHIPS` | `1164` | `0` |
| `SENTRY_DSN` | не задана | DSN проекта |

Остальные пороги (`WITHDRAWAL_MIN_CHIPS` 1000, `WITHDRAWAL_MAX_CHIPS` 2 500 000,
`WITHDRAWAL_DAILY_LIMIT_CHIPS` 50 000) оставить по умолчанию либо задать явно.

⚠️ **Любой новый ключ в `.env` нужно продублировать в `environment:` файла
`docker-compose.prod.yml`** — compose пробрасывает переменные явным списком, а не целиком.
На эти грабли проект наступал дважды (`CRYPTO_PAY_TOKEN`, затем `WITHDRAWAL_*`).

- [ ] Все ключи из таблицы выше в списке `environment:` уже есть, **кроме `SENTRY_DSN`
      (проверено 2026-07-25 — его там нет)**. Прописанный только в `.env`, он до контейнера не
      дойдёт, `Sentry.init` не выполнится, и алерты инварианта останутся в логах. Добавить строку
      `SENTRY_DSN: ${SENTRY_DSN:-}` в `docker-compose.prod.yml` — это правка кода, значит коммит
      и деплой, а не просто редактирование `.env` на сервере.

## SQL чистки

Выполнять **при остановленном `app`** (см. фазу 3). Файл кладётся на сервер и запускается через
`-f`, а не `-c`: вложенные кавычки PowerShell → ssh → psql не выживают.

```bash
scp wipe-for-mainnet.sql root@tgp.isgood.host:/opt/tg-poker/
ssh root@tgp.isgood.host "cd /opt/tg-poker && \
  docker compose -f docker-compose.prod.yml cp wipe-for-mainnet.sql postgres:/tmp/w.sql && \
  docker compose -f docker-compose.prod.yml exec -T postgres psql -U poker -d poker_db -f /tmp/w.sql"
```

```sql
-- wipe-for-mainnet.sql — обнуление testnet-экономики перед боевым запуском.
-- Аккаунты, псевдонимы и аватары СОХРАНЯЮТСЯ: удаляются только деньги и их история.
-- ⚠️ Колонки сессии и аватара — camelCase БЕЗ @map, писать в кавычках:
--    "currentChips", "currentTableId", "currentSeat", "avatarId".
--    balance / telegram_id / display_name / is_bot — обычные snake_case.

\echo '=== ДО: балансы и леджер ==='
SELECT telegram_id, display_name, balance, "currentChips" FROM users
WHERE balance <> 0 OR "currentChips" IS NOT NULL ORDER BY telegram_id;
SELECT type, status, count(1) AS rows, sum(amount) AS chips
FROM transactions GROUP BY type, status ORDER BY type;

BEGIN;

-- 1. Деньги: балансы всех аккаунтов (игроки, боты, house 0, bankroll -1000000)
--    и удержанные сессионные стеки.
UPDATE users
SET balance = 0,
    "currentChips" = NULL,
    "currentTableId" = NULL,
    "currentSeat" = NULL;

-- 2. Леджер целиком: testnet-инвойсы в боевом API не существуют, реконсиляция
--    по их external_id всё равно ничего не найдёт, а инвариант должен стартовать
--    с нуля (baseline = 0).
DELETE FROM transactions;

-- 3. Игровая статистика профилей — косметика, чтобы боевые профили начинались с чистого листа.
UPDATE users
SET hands_played = 0, hands_won = 0, total_winnings = 0, biggest_pot = 0;

-- 4. История раздач: тестовый шум в экране истории игрока.
--    На порог §I не влияет (он считает руки ПОСЛЕ последнего депозита, а депозитов
--    после чистки не будет ни одного), так что пункт опциональный.
DELETE FROM "HandHistory";

COMMIT;

\echo '=== ПОСЛЕ: всё должно быть пусто/нулевое ==='
SELECT count(1) AS nonzero_balances FROM users WHERE balance <> 0;
SELECT count(1) AS held_sessions FROM users WHERE "currentChips" IS NOT NULL;
SELECT count(1) AS ledger_rows FROM transactions;
SELECT count(1) AS users_kept FROM users;   -- аккаунты остаются на месте
```

**Что НЕ трогаем:** `"AdminAuditLog"` — журнал действий администратора, его ценность в полноте;
таблицу `users` не удаляем, чтобы игроки сохранили псевдонимы, аватары и принятый ToS.

## Откат

Если после переключения выяснится, что боевое приложение непригодно (например, провайдер
запретил тематику):

1. `docker compose -f docker-compose.prod.yml stop app`
2. Вернуть в `.env` testnet-токен и `CRYPTO_PAY_TESTNET=true`.
3. Восстановить состояние из `backup-pre-mainnet.sql`, если нужны прежние данные, и вернуть
   `MONEY_INVARIANT_BASELINE_CHIPS=1164`.
4. `bash update.sh`.

Отката для уже отправленных боевых переводов не существует — поэтому smoke делается
на минимальных суммах.

## Открытые вопросы

- Комиссия `transfer` на mainnet: на testnet её нет (списывается ровно сумма перевода).
  Если на боевом она появится, игрок получит меньше запрошенного — тогда нужно будет
  показывать её на экране вывода так же, как показывается комиссия депозита.
- Порог `WITHDRAWAL_MIN_HANDS=50` выбран по исходному плану и ни разу не проверялся на живой
  аудитории; после запуска, вероятно, потребует настройки (меняется через `.env` без деплоя).
