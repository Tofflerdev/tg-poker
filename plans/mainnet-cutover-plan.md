# План: запуск боевого сервера (mainnet, реальные деньги)

Составлен 2026-07-25 по итогам полного прогона фаз 1–6 плана `crypto-payments-rake-plan.md`
на testnet. **Переработан 2026-08-04**: решено поднимать боевой прод на **отдельной машине**,
а текущий сервер оставить тестовым стендом. До этого план описывал переключение токенов

## Топология после запуска

| | Боевой прод | Тестовый стенд (нынешний сервер) |
|---|---|---|
| Машина | **новая, ещё не заведена** | `tgp.isgood.host` |
| Crypto Pay | боевое приложение @CryptoBot | testnet «Buckram Wisent App» |
| Бот | боевой | `Testpoke_bot` |
| БД | **пустая с нуля** | как есть |
| `SENTRY_ENVIRONMENT` | `production` | `staging` |
| Домен | **новый**, ещё не выбран | `tgp.isgood.host` (остаётся) |
| Аккаунты игроков | **чистый старт**, ничего не переносим | остаются как есть |

**Главное следствие новой схемы:** чистка экономики (в прежней версии — самая опасная фаза)
**отпадает**. Боевая база стартует пустой, минтить нечего, `MONEY_INVARIANT_BASELINE_CHIPS`
естественным образом `0`. Testnet-фишки остаются на стенде, где им и место.

**Взамен появляется риск другого рода:** боевую машину нужно собрать с нуля, ничего не забыв —
SSL, бэкапы, крон, переменные. Забытый бэкап на боевой базе хуже, чем забытый на стенде.

## Фаза A. Провижининг боевой машины

Пошаговая инструкция — `DEPLOY.md`, раздел «First-time setup (new VPS)». Здесь только то,

### A1. Домен — РЕШЕНО 2026-08-05

**`tgp.isgood.host` остаётся за тестовым стендом. Боевая машина получает новый домен.**
Ничего не перевешиваем: A-запись стенда, его сертификат и URL тестового бота не трогаем.

⚠️ **Из этого следует работа, которой раньше в плане не было.** Обе машины деплоятся
из одного репозитория и одного `main`, а домен зашит в код и в конфиг, а не в `.env`:

- `server/index.ts:108-109` — в проде `CORS_ORIGIN` это литерал `["https://tgp.isgood.host"]`.
  На боевой машине сокеты и `/api/admin/login` с нового домена получат отказ CORS.
- `nginx/nginx.conf:7,21,24,25` — `server_name` и пути к сертификату Let's Encrypt,
  которые содержат имя домена.

Пока домен был один на всё, литералы работали. С двумя машинами один и тот же файл
должен обслуживать два имени — значит домен нужно параметризовать **до** провижининга:

- [ ] **`CORS_ORIGIN` из окружения.** `process.env.CORS_ORIGIN?.split(',')` с падением
      на нынешний литерал, плюс ключ в `environment:` compose. Заодно позволит держать
      в списке оба домена, если понадобится.
- [ ] **`nginx.conf` → шаблон.** Образ `nginx:alpine` сам прогоняет `envsubst` по
      `/etc/nginx/templates/*.template` и кладёт результат в `conf.d/`. Переименовать в
      `nginx/default.conf.template`, монтировать **каталог** `./nginx` в
      `/etc/nginx/templates`, подставлять `${DOMAIN}`.
      ⚠️ **Обязательно задать `NGINX_ENVSUBST_FILTER: DOMAIN`** — иначе envsubst съест
      и `$host`, `$uri`, `$remote_addr`, `$http_upgrade` и остальные переменные самого
      nginx, которых в конфиге около двадцати, и прокси развалится.
- [ ] Проверить **на стенде**: с `DOMAIN=tgp.isgood.host` итоговый конфиг обязан совпасть
      с нынешним. `docker compose exec nginx cat /etc/nginx/conf.d/default.conf` —
      сравнивать то, что **внутри контейнера**, а не на хосте.

Побочная выгода: монтирование каталога вместо одиночного файла снимает грабли с inode —
`git pull` больше не подменяет файл под работающим контейнером.

### A4. Аккаунты игроков — РЕШЕНО 2026-08-05: чистый старт

**Ничего не переносим, боевая база стартует пустой.** Игроки заново вводят имя и принимают
ToS; на стенде их аккаунты остаются нетронутыми.

Что это даёт: **приложение с SQL чистки не нужно вовсе.** Ни дампов, ни восстановления,
ни остановки `app` ради обнуления балансов — то есть самый опасный сценарий прежнего плана
(фишки, обеспеченные testnet-USDT, превращаются в право вывести реальные деньги) в новой
схеме физически невозможен. `MONEY_INVARIANT_BASELINE_CHIPS=0` верен с первой секунды.

Единственная плата — тестировавшиеся игроки на боевом старте будут новыми пользователями.

## Приложение: SQL чистки экономики

**НЕ НУЖЕН при выбранном варианте.** В A4 решено стартовать с пустой базы, так что чистить
нечего. Оставлен только на случай, если решение о переносе аккаунтов будет пересмотрено —
и тогда всё описанное ниже снова обязательно. Выполнять **при остановленном `app`**: `TableManager` держит стеки
сидящих игроков в памяти, они переживут чистку БД и вернутся на баланс при выходе — минтинг.

Файл кладётся на сервер и запускается через `-f`, а не `-c`: вложенные кавычки
PowerShell → ssh → psql не выживают.

```bash
scp wipe-for-mainnet.sql root@<боевой хост>:/opt/tg-poker/
ssh root@<боевой хост> "cd /opt/tg-poker && \
  docker compose -f docker-compose.prod.yml cp wipe-for-mainnet.sql postgres:/tmp/w.sql && \
  docker compose -f docker-compose.prod.yml exec -T postgres psql -U poker -d poker_db -f /tmp/w.sql"
```

```sql
-- wipe-for-mainnet.sql — обнуление перенесённой testnet-экономики.
-- Аккаунты, псевдонимы и аватары СОХРАНЯЮТСЯ: удаляются только деньги и их история.
-- ⚠️ Колонки сессии и аватара — camelCase БЕЗ @map, писать в кавычках:
--    "currentChips", "currentTableId", "currentSeat", "avatarId".
--    balance / telegram_id / display_name / is_bot — обычные snake_case.

\echo '=== ДО: балансы и леджер ==='
SELECT telegram_id, display_name, balance, "currentChips" FROM users
WHERE balance <> 0 OR "currentChips" IS NOT NULL ORDER BY telegram_id;
SELECT type, status, count(1) AS rows, sum(amount) AS chips
FROM transactions GROUP BY type, status ORDER BY type;

BEGIN;

-- 1. Деньги: балансы всех аккаунтов (игроки, боты, house 0, bankroll -1000000)
--    и удержанные сессионные стеки.
UPDATE users
SET balance = 0,
    "currentChips" = NULL,
    "currentTableId" = NULL,
    "currentSeat" = NULL;

-- 2. Леджер целиком: testnet-инвойсы в боевом API не существуют, реконсиляция
--    по их external_id всё равно ничего не найдёт, а инвариант должен стартовать
--    с нуля (baseline = 0).
DELETE FROM transactions;

-- 3. Игровая статистика профилей — косметика, чтобы боевые профили начинались с чистого листа.
UPDATE users
SET hands_played = 0, hands_won = 0, total_winnings = 0, biggest_pot = 0;

-- 4. История раздач: тестовый шум в экране истории игрока.
--    На порог §I не влияет (он считает руки ПОСЛЕ последнего депозита, а депозитов
--    после чистки не будет ни одного), так что пункт опциональный.
DELETE FROM "HandHistory";

COMMIT;

\echo '=== ПОСЛЕ: всё должно быть пусто/нулевое ==='
SELECT count(1) AS nonzero_balances FROM users WHERE balance <> 0;
SELECT count(1) AS held_sessions FROM users WHERE "currentChips" IS NOT NULL;
SELECT count(1) AS ledger_rows FROM transactions;
SELECT count(1) AS users_kept FROM users;   -- аккаунты остаются на месте
```

**Что НЕ трогаем:** `"AdminAuditLog"` — журнал действий администратора, его ценность
в полноте; таблицу `users` не удаляем, чтобы игроки сохранили псевдонимы, аватары
и принятый ToS.
